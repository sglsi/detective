## 0. 问题：设计侧权重在运行时坍缩

上一轮对核心设计文档的线索类型分析结论：

- 设计文档定义了线索「五分类等级」：**关键(10) / 重要(5) / 一般(2) / 其他(0) / 误导(0)**，并配套标签、可信度体系。
- 但运行时机制把这些等级**坍缩为仅 `correct: bool` 一个二值**：
  - `ClueSystem.collect_clue(id, name, desc, correct, source)` 不接收、不存储任何权重；
  - `StarRatingSystem.add_observation(count)` 原按**等权计数**累加（每收集 1 条 +1），`max_observation = 45`（≈线索条数）；
  - 10/5/2 的权重差完全未参与评分 → 收集一条「误导」和一条「关键」，对观察力星级的贡献**完全相同**。

这违背了设计文档「线索重要性分层驱动评价」的初衷。P3.1 的目标：**把分级权重在运行时真正落地为加权评分**，同时严格保持既有架构健康度：

1. **双路径统一漏斗不变**——观察器（热点）与对话（`trigger=="clue"` + `grants_clues`）仍共用 `ClueSystem.collect_clue_from_catalog` 单一真相源；
2. **幂等不变**——同一线索重复收集不增条目、不叠权重；
3. **误导恒 0 分**——`correct:false` 的线索权重强制为 0，不污染星级；
4. **不另造 tier 桶**——权重直接取既有数据，避免引入新的双源/平行实现。

## 1. 关键发现：权重从哪来（避免另造轮子）

实测 12 个 `data/clues/*.tres` 与运行时短 id 线索的 `importance` 字段，**作者已按「权重值」口径写入**，实测取值为 `10 / 5 / 4 / 3 / 2`（不是 1–5 等级）：

- `wrist`（目录 `.tres`，`importance = 10`）→ 即「关键」权重；
- 其余多为 5 / 4 / 3 / 2。

因此**目录线索直取 `.tres` 的 `importance` 作为权重**，无需再造 tier→weight 映射桶。内联构造的线索（scene4–8 对话/热点，无 `.tres`）用 `inline_weight` 字段提供权重，缺省回退 2（一般）。

层次优先级（在 `weight_of` 中落地）：

```
若 correct == false → 权重 = 0（误导，恒 0 分，tier = "误导"）
否则：
  1) 取目录 .tres 的 importance（仅当该线索有对应 .tres 且 importance 有效）
  2) 否则取调用方传入的 inline_weight（场景内联表）
  3) 两者皆缺 → 回退 2（一般）
```

## 2. 命名约定：热点权重字段冲突已规避

- `scene7/8` 的 `HOTSPOTS` 字典**已用 `"w"` 表示热点矩形宽度**（如 `"w":220`）。若热点权重也用 `"w"`，会误把宽度当权重。
- 故约定：
  - **热点权重** → 用 `"wt"`（width-tier 缩写），`"w"` 保留为矩形宽度；
  - **对话 `CLUES` / `DIALOGUE_CLUES`** → 用 `"w"`（无宽度冲突，直接用）。
- `detective_scene.gd` 三处观察器采集全部改读 `"wt"`；恢复非热点对话线索时从 prior 副本回收 `"weight"` 字段。

## 3. 改动清单（diff 级）

### 3.1 `autoload/clue_system.gd`（核心，#98）

`collect_clue` 增 `weight:int=0` 参数，登记时附 `"weight"` 与派生的 `"tier"`（快照/恢复天然兼容新增字典字段，无需改）：

```gdscript
func collect_clue(id: String, name: String, desc: String, correct: bool, source: String = "", weight: int = 0) -> void:
    var tier := tier_label(weight, correct)
    for c in collected_clues:
        if c.get("id", "") == id:
            c["name"]=name; c["desc"]=desc; c["correct"]=correct
            c["source"]=source; c["weight"]=weight; c["tier"]=tier
            return
    collected_clues.append({"id":id,"name":name,"desc":desc,"correct":correct,"source":source,"weight":weight,"tier":tier})
```

`collect_clue_from_catalog` 增 `inline_weight:int=-1`，权重经 `weight_of` 计算：

```gdscript
func collect_clue_from_catalog(id, name, desc, correct, source:="", inline_weight:=-1) -> void:
    var def = get_clue_definition(id)
    var w := weight_of(id, correct, inline_weight)
    if def != null:
        collect_clue(id, def.name if def.name!="" else name, def.description if def.description!="" else desc, correct, source, w)
    else:
        collect_clue(id, name, desc, correct, source, w)

func weight_of(id: String, correct: bool, inline_weight: int = -1) -> int:
    if not correct: return 0
    var def = get_clue_definition(id)
    if def != null: return int(def.importance)
    return inline_weight if inline_weight >= 0 else 2

func tier_label(weight: int, correct: bool) -> String:
    if not correct: return "误导"
    if weight >= 10: return "关键"
    if weight >= 4: return "重要"
    if weight >= 2: return "一般"
    return "其他"

func total_weight(source: String = "") -> int:
    var sum := 0
    for c in collected_clues:
        if source == "" or c.get("source","") == source: sum += int(c.get("weight",0))
    return sum
```

## 4. tier 派生规则（展示用，不参与评分计算）

| weight | correct | tier 标签 | 说明 |
|--------|---------|-----------|------|
| – | false | **误导** | 恒 0 分，不污染星级 |
| ≥ 10 | true | **关键** | 核心证据 |
| 4–9 | true | **重要** | 指向性证据 |
| 2–3 | true | **一般** | 辅助线索 |
| < 2 | true | **其他** | 边缘信息（当前数据未出现） |

`tier` 仅由 `weight` + `correct` 派生，随线索登记写入 `collected_clues` 字典，供推理墙 / 线索面板展示，不影响评分数学（评分只看 `weight` 累加）。
