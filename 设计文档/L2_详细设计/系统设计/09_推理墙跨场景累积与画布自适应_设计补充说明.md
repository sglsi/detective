## 0. 玩法意图（总纲）

```
场景二墙（线索+推断+结论+关系）
   │ 进入场景三：上一步全部内容带入（不折叠、位置重算）
   ▼
场景三墙 = 场景二全部内容 ∪ 场景三新收集的线索及其推断/结论
   │ 玩家依据两场景线索共同推理，形成场景三的关系（可连旧节点到新线索）
   ▼
场景四墙 = 场景三全部内容 ∪ 场景四新内容
   ⋯ 以此类推（场景 N = 场景 2~N-1 全部 ∪ N 新内容）
```

四条硬约束（思傅原话）：

1. **带入范围**：线索 + 推断 + 结论 + 玩家建立的**全部相互关系**；**不带入文本框位置**（进入新场景重新布局）。
2. **同一人物合并**：若相邻场景共用一个人物，墙中只出现该人物**一个节点**（不重复），并作为连接两场景内容的锚点保持可见。
3. **玩家全程自主折叠/展开**：想看的展开、当前不重要的折叠省篇幅；不强制折叠、不自动折叠。
4. **画布随内容增加自适应扩展**：内容多了画布应随之铺开，玩家靠平移/缩放/折叠查看局部，不存在"挤到字看不清"。

## 1. 根因诊断（为什么当前"带入不全 / 信息缺失"）

实测（`tools/test_scale_flat.gd`，构造场景八全并集 68 节点）定位到**三层缺陷**：

### 1.1 节点只取当前场景预设（内容漏带 · 第一层）

`graph_view_controller.gd` 的 `_node_list_raw`（约 L1706）从 `_hypo["battlefield"]["hypotheses"]` 读推断/结论节点 —— 而 `_hypo` 是**当前场景** `sceneN.reasoning_hypothesis()` 的返回值。

- 场景二的 `H2-*` / `CL2-*` 只在场景二预设里；
- 进入场景三，`reasoning_hypothesis()` 返回 `H3-*` —— `H2-*` 不在节点集里；
- 但共享 `case_wall_state["_relations"]` 里存着场景二画的边（如 `H2-01 → CL2-01`）→ 这些边**找不到端点，变孤儿边被丢弃** → 关系只带一部分。

**关键洞察**：场景二~八 各场景的推断/结论是**各写死在 `sceneN.gd` 里的预设**，缺乏一个跨场景的"节点真相源"。这层要建一张表修。

### 1.2 进入新场景自动折叠吞掉内容（信息缺失 · 第二层 · 更致命）

`reasoning_wall.gd` L216-217：`_auto_fold = auto_fold` 且 `_case_wide = auto_fold`（**同一参数驱动两个开关**，`detective_scene.gd` L441 把 `use_case_wide` 当 `auto_fold` 传入）。`_auto_fold=true` 时 `graph_view_controller.gd` L366-375 调 `_apply_fold_to_roots()`：

- `_compute_hidden()`（graph_view_fold.gd L98）：从每个折叠根 BFS，隐藏所有 `_ring_depth > 根_rd` 的节点及其传递闭包。
- 人物 `rd=0` 为最高层，`_apply_fold_to_roots` 判"无父有子"时人物天然命中 → 人物被折叠 → 其下结论/推断/线索**全部隐藏**。
- 实测：场景八全并集进入时，自动折叠后**可见节点 0 / 68**，画布塌到只剩人物节点。

⇒ 思傅抱怨"只有部分带入"，第一层是节点漏带，第二层（更致命）是**自动折叠把内容全藏了**。"不再折叠"的直觉完全正确。

### 1.3 画布扩展只实现一半（"挤"的真因）

- ✅ **视口层（无限画布）已实现**：`_canvas` 为 FULL_RECT Control 世界；平移 `_canvas.position += gp - _pan_last`（**无边界钳制**）；滚轮缩放 `_zoom_at` clamp `[0.4, 2.5]`；`fit_view()` clamp `[0.35, 1.6]`；顶栏有「适应画布」按钮（`reasoning_wall.gd` L446/988）。
- ❌ **自动布局层（随内容扩展）未实现**：`graph_view_layout.gd` L286 调用的 `_clamp_to_canvas` 把所有节点中心 clamp 到 `[60, cv.x-60] × [60, cv.y-60]`，`cv` 取 `owner._canvas.size`（≈ 1920×1080）。

⇒ 68 节点内容包围盒 2440×2205，中心却被压进 1920×1080 框 → 实测 **4 对重叠**。**重叠真因是钳制，不是节点多**。修掉钳制（按内容包围盒动态扩展）即根除，与是否折叠无关。

### 1.4 附带临界值

全平铺看全需 `scale ≈ 0.408`，而滚轮缩放下限 `0.4` → 手动缩到底**差一点看不全**；`fit_view` 下限 `0.35` 能看全但字很小。可顺手把下限放宽到 `0.25`。

## 2. 设计决策

### 2.1 一张表：全场景节点真相源 + 检索/对照层

新建 `data/case_reasoning_registry.gd`（只读预设，建表于游戏启动 / 首次开墙）：

- 聚合 `scene2~8` 各自的 `reasoning_hypothesis().battlefield.hypotheses`（推断）+ `.conclusions`（结论）为统一表，按节点 `id` 索引，标注 `scene_id`、来源、文本、target（`person:`/`event:`）、gate 关系等。
- 对外接口：
  - `get_all_nodes() -> Dictionary`：全部推断/结论节点的并集（key=id）；
  - `get_node(id) -> Dictionary`：单节点详情；
  - `get_scene_nodes(sid) -> Array`：某场景的预设节点 id 列表；
  - `get_relations() -> Array`：各场景预设的 `support`/`target` 边（供"带入"时还能带"预设关系"，与玩家自建边合并）。
- 这张表**同时满足思傅说的"全局各场景相关信息的获取、检索、对照"诉求**——它是一处权威真相源，消除"预设散落在 scene2~8.gd"的治理问题。
- 实现方式（二选一，落地时定）：A）启动期遍历各场景脚本调用其 `reasoning_hypothesis()` 静态/实例方法聚合；B）手动从 scene2~8 抽出预设写进静态表（后续随剧情变化人工同步）。倾向 A（自维护、不漂移），若场景函数不便静态调用则退 B。

### 2.2 墙节点集改为"并集"

`graph_view_controller.gd` 的 `build` / `_node_list` / `_node_list_raw` 在 `case_wide` 模式下：

- 节点集 = `并集( 表内全部 H*/CL* (get_all_nodes) ∪ 本场景全案线索池 (ClueSystem.get_collected) ∪ state 内自定义/派生节点 (custom/conclusion) )`，替换现在"只取当前场景 `_hypo`"。
- 这样共享 `case_wall_state["_relations"]` 里**所有关系边**都能找到两端点 → 完整带入，不再丢关系。
- 本场景 `sceneN.reasoning_hypothesis()` 仍用于**本场景新线索推进**（候选推断采纳，见 `07`），不再作为"全案节点唯一来源"。

### 2.3 去掉自动折叠，保留玩家手动折叠

- 删除 `if _auto_fold:` 分支内的 `_apply_fold_to_roots()` + 第二次 `_rebuild_graph()`（graph_view_controller.gd L366-375）。
- **保留** `_set_folded` / `_compute_hidden` 整条手动折叠链路 —— 它是 XMind 语义（折父收起更深层子节点），行为正常、玩家可用。
- **解耦陷阱（必做）**：`_case_wide = auto_fold` 与 `_auto_fold = auto_fold` 同源于一个参数（`detective_scene.gd` L441 传 `use_case_wide`）。
  - 若简单把 `auto_fold` 置 `false`，`_case_wide` 会跟着变 `false` → L694 `if _case_wide:` 失效 → **人物节点只剩焦点人物一个**，人物又"丢失"。
  - 改造：`reasoning_wall.gd` 的 `setup(...)` 增加独立 `case_wide` 参数（或拆 `_auto_fold` 与 `_case_wide` 为两个入参）；`detective_scene.gd` 传 `case_wide = use_case_wide`、`auto_fold = false`。

### 2.4 画布随内容自适应扩展（核心修复）

- 改造 `_clamp_to_canvas`（graph_view_layout.gd）：去掉对 `cv = _canvas.size` 的硬钳制。改为：
  - 节点落点**不限制**在固定矩形内（仅留最小安全边距 `m`，防负坐标）；
  - 或按本次布局的**内容包围盒**动态扩展画布逻辑尺寸（若引擎需要画布有 size，则把 `_canvas` 的 `custom_minimum_size` 设为包围盒尺寸）。
- 配合：顶栏「适应画布」(`fit_view`) 在内容多时自动缩放到看全（仍受缩放下限约束，见 2.6）；玩家可平移到局部细看。
- 手动拖动节点本就不钳制（`_canvas.position` 无约束），修复后自动布局与手动布局一致（都无限画布）。

### 2.5 保留"携带内容 / 新内容"左右分区（已实现，零成本）

`graph_view_layout.gd` L239/248/274 已有：携带内容偏左 `center.x-380`、本场景新内容偏右 `center.x+380`，**纯位置摆放、不隐藏任何节点**。

- 该逻辑由 `_carried_ids` 触发，而 `_carried_ids` 当前只在 `if _auto_fold:` 内计算（L370-373）。
- 去掉自动折叠后，把 `_carried_ids` 计算**移出**该分支、始终计算（携带内容 = 开墙时已存在且非本场景新收集线索的节点），左右分区即自动生效 —— 既满足"带入内容不遮盖新线索"，又不引入新折叠。

### 2.6 缩放下限放宽

`_zoom_at` clamp `[0.4, 2.5]` → `[0.25, 2.5]`；`fit_view` clamp `[0.35, 1.6]` → `[0.25, 1.6]`（让全案大墙能缩到看全）。

### 2.7 位置不沿用（带入不含位置）

`graph_view_controller.gd` L326-331 `if _auto_fold:` 内清空 `graph_node_positions` / `graph_root_anchors` —— 这段"位置重算"行为**保留并移出**自动折叠分支（进入新场景一律重算位置，达成"带入不含位置"）。

## 3. 数据模型（表）

```gdscript
# data/case_reasoning_registry.gd
extends RefCounted
class_name CaseReasoningRegistry

# 全案推断/结论节点真相源（只读预设），按 id 索引
var _nodes: Dictionary = {}      # id -> {id, kind:"hypo"|"conclusion", scene_id, text, target, gate_clue_ids}
var _relations: Array = []       # 预设 support/target 边：{from, to, kind}

func _ready() -> void:           # 或在首次 get_all_nodes 时惰性构建
    _build_from_scenes()

func _build_from_scenes() -> void:
    # 遍历 scene2~8，调用其 reasoning_hypothesis().battlefield，聚合 hypotheses+conclusions
    # （实现方式见 2.1，A/B 选一）
    pass

func get_all_nodes() -> Dictionary: return _nodes
func get_node(id: String) -> Dictionary: return _nodes.get(id, {})
func get_scene_nodes(sid: String) -> Array:
    var out := []
    for k in _nodes:
        if _nodes[k].get("scene_id", "") == sid: out.append(k)
    return out
func get_relations() -> Array: return _relations
```
