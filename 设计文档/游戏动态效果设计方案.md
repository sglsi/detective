### 0.3 ⚠️ 2026-09-12 浏览器实测：两处"氛围层从未生效"根因（已修）

**缘起**：外部《可行性分析与实施建议》提出"浮尘在 Web 端从未显示"，并把原因归于"Compatibility 不支持 GPUParticles"。经**真实浏览器实测**（Chrome + 本地 8090 服务 + 主菜单对照实验）核对——**该归因错误，但"现象"另有真因**：

| 结论 | 核实 |
|---|---|
| "Compatibility 不支持 GPUParticles（引擎硬限制）" | ❌ **错误**。官方渲染器对比表中 Compatibility 明确不支持的**粒子项只有** `Particle trails`（拖尾）与 `Particle SDF collision`；`GPUParticles2D/3D` 节点本身受支持。主菜单放「红=GPUParticles2D / 绿=CPUParticles2D + 蓝=ColorRect 正对照」实测**三者全部渲染**。因此**无需**换成 CPUParticles。 |
| "浮尘（乃至整个氛围层）在场景一从未显示" | ✅ **现象属实**，但**真因不是引擎限制**，而是下面两条本项目自身的 bug。 |

**根因 A（影响所有场景）：雾/暗角/灯光叠加层一直 0×0、不可见。**
`SceneFramework._apply_atmosphere()` 创建的 `AtmosphereLayer`（一个 `Control`）**从未设置自身 `size`**；其内部雾/暗角 `ColorRect` 用 `PRESET_FULL_RECT` 锚点 → 退化为 **0×0**。而**浮尘是 `GPUParticles2D`（Node2D，用绝对坐标）所以照常显示**——正是它掩盖了这个 bug，使"氛围层已落地"在文档层面看起来成立。
**修复**：`layer.size = _world.size`（+ `layer.mouse_filter = IGNORE`）。

**根因 B（仅场景一）：场景一完全没有氛围层。**
`scene1._build_ui()` 调 `_ui.setup(...)` **漏传第 5 参 `scene_id_arg`** → `_scene_id = ""` → `_apply_atmosphere()` 里 `SCENE_ATMOSPHERE.has("")` 为假 → 直接 return。（基类 `detective_scene.gd:78` 是带 `scene_id()` 的，故 **scene2~8 正常、仅 scene1 缺失**。）
**修复**：补 `[], scene_id()`。

**实测确认**：修复后场景一出现雾 + 煤气灯暖光 + 浮尘（其余室内场景同源受益）。

**教训（写进流程）**：
1. **"节点建了" ≠ "看得见"**：`Control` 尺寸为 0 时，锚点布局的子节点会**静默消失**（无报错）。此类 bug 只有真机/真浏览器目视才能发现 → 氛围/渲染类改动必须过一次 Web 目视验收。
2. **别轻信"引擎不支持"就换实现**：先查官方渲染器对比表，再做**最小对照实验**（放一个必定渲染的正对照，排除"新包没加载"的假阴性），再下结论。

**顺带修正的文档错误**：v2.0 的 §5.1 曾把"氛围层（雾/灯光/暗角）"标为 ✅ ——实为**仅在代码存在、从未渲染**；本版已改。

## 2. 核心设计思路

**把"一张背景图"理解为"场景要素清单"**：图中的门、壁炉、窗、灯、家具拆成独立节点，叠上程序化基底、着色器氛围、角色 Juice 与镜头调度。

- 每个要素可独立动画（门可开、灯可闪、窗帘可摇）；
- 氛围可随剧情/玩法实时切换（取证成功→房间变亮、终局→暗角收紧）；
- 角色不需骨骼，靠差分 + Tween 做到 AVG 级演出；
- **镜头是"第二叙事者"**：推近制造焦点，框选保证信息完整。

## 5. 场景动态方案

### 5.1 氛围动态

> ✅ **2026-09-12 起才真正生效**：此前雾/暗角/灯光三层叠加因 `AtmosphereLayer` 尺寸为 0 而从未渲染（见 §0.3 根因 A）。

| 效果 | 实现 | 状态 |
|------|------|------|
| 煤气灯暖光闪烁 | shader `lamp_glow_intensity` / `lamp_glow_radius` | ✅ 灯位已对齐各背景**真实灯/烛/炉火**（见下表） |
| 雾气 | shader `fog_density` / `fog_color` | ✅ |
| 暗角（终局收紧） | shader `vignette_strength` | ✅ 已按场景配（scene8=1.25 最强） |
| 浮尘粒子 | `GPUParticles2D`（60 颗，无拖尾 / 无 SDF 碰撞） | ✅ **仅室内场景开启**（室外街景关闭） |
| 窗帘摇曳 / 雨雪 / 昼夜切换 / 取证点亮 | 需要素级拆分 | ❌ 待 Tier 2 |

**浮尘使用策略（2026-09-12 定）**：浮尘适合**有自然光/灯光的室内**（贝克街会客厅、旅馆房间等），是标准的室内氛围；**室外街景（scene2）关闭**——街面上飘尘读感不对，该处的雾/湿地面已足够。故按场景 `dust` 开关控制，**不做全局取消**。

**为什么用浮尘（作用与可达效果）**：一句话——**给"空气"一个可见的介质**，让光、空间、时间"显形"，把静态背景从"贴图"变成"活的场景"。

| 作用 | 原理 | 观感 |
|---|---|---|
| 让光可见 | 尘埃是光的"示踪剂"——有介质才看得到光束 | 窗光/灯光成为能"摸到"的体积光，而非一块亮斑 |
| 制造纵深 | 近处尘大而清、远处小而糊，提供距离线索 | 扁平 2D 画面出现前/中/后层次，缓解"平" |
| 画面不死 | 极缓慢漂浮是场景中唯一的"自发运动" | 静止对话场景仍有呼吸感，不像死图 |
| 年代与情绪 | 灰尘是"时间流逝"的符号 | 静谧 / 怀旧 / 尘封；配暖光=温馨安全，配冷光=废弃阴森 |
| 叙事暗示（延伸） | 灰尘浓度可"讲故事" | 久无人住的房间、阁楼——无需台词即传达"很久没人来" |

**实现要点**：每场景 60 颗，柔边暖白点（alpha≈0.45），**缓慢上浮**（模拟室内暖气/气流，而非随风狂飘）；挂世界坐标，随摄像机缩放/平移，推近时尘埃同步放大 → 纵深线索成立。定位是**"氛围底噪"**，克制、不抢戏。

**用好 / 别用**：
- ✅ **最佳落点**：有**窗光或暖灯的室内**（本作 scene1 窗光、scene5/6 炉火暖光）；**必须与雾/暗角/灯光叠加**才成体系——单独用浮尘效果很弱。
- ❌ 室外街景（scene2 已关）；❌ 过量/过亮 → 像噪点或下雪、显脏、干扰点线索；❌ 颗粒过大 → 像飞虫、变假。

**已配置的 8 场景氛围参数**（`scene_framework.gd: SCENE_ATMOSPHERE`；灯位 UV 为场景区归一化坐标，按各背景实测）：

| 场景 | 类型 | 暗角 | 雾浓度 | 雾色 | 灯位（真实灯/炉火 UV） | 灯强 | 浮尘 |
|---|---|---|---|---|---|---|---|
| scene1 / sceneX | 室内·会客厅 | 0.95 | 0.20 | 暖褐 | (0.90,0.42) 壁炉台烛台 / (0.91,0.62) 炉火 | 1.0 | 开 |
| scene2 | 室外·花园街 | 1.05 | 0.30 | 冷蓝 | (0.90,0.42) 街灯 | 0.7 | **关** |
| scene3 | 室内·昏暗现场 | 1.00 | 0.24 | 暖褐 | 无灯/烛 → 不点亮 | — | 开 |
| scene4 | 室内·昏暗房间 | 1.10 | 0.34 | 冷蓝 | 无灯/烛 → 不点亮 | — | 开 |
| scene5 | 室内·会客厅(炉火) | 1.00 | 0.22 | 暖褐 | (0.12,0.28) 壁灯 / (0.37,0.78) 壁炉火 | 1.0 | 开 |
| scene6 | 室内·维多利亚室 | 1.00 | 0.26 | 中性 | (0.10,0.68) 壁炉 / (0.87,0.48) 台灯 | 0.95 | 开 |
| scene7 | 室内·旅馆（复用图） | 1.15 | 0.28 | 冷紫 | 同 scene6（复用同一张图） | 0.9 | 开 |
| scene8 | 室内·终局（复用图） | 1.25 | 0.28 | 暖褐 | 同 scene5（复用同一张图） | 1.1 | 开 |

> 设计意图：暖褐=室内安全区（贝克街）、冷蓝=室外/警局（理性调查）、冷紫=深夜旅馆（危险）、scene8 暗角+灯强最高（终局张力）。
> **灯位规则**：只在该场景背景**真实存在灯/蜡烛/炉火**的位置点亮；灯/烛较多的场景最多点亮 **1–2 处最亮者**；无光源的昏暗房间**不点亮**（仅保留窗光/雾/暗角）。

### 5.2 镜头系统（v1.0 方案缺失，本章为补充）

镜头是本作已成型的核心动态能力，但原方案未系统描述。现有 API（`scene_framework.gd`）：

| API | 用途 | 典型调用 |
|---|---|---|
| `focus_world_point(pt, zoom)` | 单点推近 | 聚焦某个刚发现的线索 |
| `frame_world_points(points, padding)` | **多点框选**：算点集包围盒→适配缩放居中，保证所有目标在视野内 | 通用工具（"一组目标都可见"时调用）；收集线索流程现改回 `reset_camera()` |
| `reset_camera()` | 回统览（zoom=1） | 阶段结束、切图前 |
| `set_camera_enabled(b)` | 锁/放玩家拖拽滚轮 | 演出期间锁输入，避免与推镜打架 |

> ⚠️ **历史缺陷回顾**：早期在收集线索后调用 `focus_world_point` 锁推近"刚记录的线索"，
> 结果把其余待收集圆圈推出视口，玩家点不到而卡关 → 已改回 `reset_camera()` 平滑回到统览（zoom=1 全可见）。
> `frame_world_points()` 仍保留作"让一组目标都在视野内"的通用工具（非收集流程使用）。
> 调用点变更：`scene1._on_collect_clue`、基类 `detective_scene._on_clue_recorded` 现均调用 `reset_camera()`（2026-09-12 回退 32d3484 的框选方案，因其每次收集都推近/缩回、观感生硬）。

|------|----------|------|
| 门 | `AnimationPlayer` 旋转/缩放开门 | 进入新区域 |
| 抽屉/柜子 | Tween 位移/旋转 | 搜证成功 |
| 窗帘 | Shader UV 摇曳 | 窗外天气 |
| 火焰/烛火 | 帧动画或 shader 扭曲 | 常态 |
| 烟雾/茶气 | `GPUParticles2D` | 常态/事件 |

### 5.4 视差分层（未实现）

远景 0.1× / 中景 0.3× / 近景 0.6× / 前景遮挡 0.9×。
`sc02_facade`、`sc02_path`、`sc02_street` 已按远/中/近分好层，具备接视差的条件。

> ⚠️ 视差要专门验一次**与镜头 zoom 的交互**（zoom≠1 时视差因子表现），且 Web 端多层半透明大图有填充率压力，远景层建议用**预暗化图**而非运行时 shader 变暗。

### 5.5 Web 性能预算与"动态效果档位"（新增，来自可行性分析）

方案此前未量化 Web 端性能红线。Compatibility + WebGL2 的填充率/粒子预算比原生紧，需明确上限：

| 项 | Web 红线 | 现状 |
|---|---|---|
| 全屏 shader 数 | ≤ 2 个 | ✅ 1 个（`fog_atmosphere` 单张全屏 ColorRect 合成，未做多层叠加） |
| 粒子总量 | ≤ 150 / 屏 | ✅ 60（每场景一处室内浮尘） |
| 目标帧率 | 60fps（低端可接受 30fps） | ⏳ 待低端设备实测 |

**建议补：设置页「动态效果：高 / 低 / 关」档位**（写入 `SettingsManager`，`SceneFramework`/`AtmosphereLayer` 按档位降级）：

- **高**：全氛围（雾 + 暗角 + 灯 + 浮尘 + 镜头呼吸 + 转场）；
- **低**：保留雾/暗角，关浮尘与镜头呼吸（省填充率）；
- **关**：全关（纯静态底图，最长续航）。

> 发布策略是**先网页后手机**，手机端必须能降级 → 该档位是**手机端发布的前置**，建议随 Tier 3 落地。

| **镜头呼吸** | 空闲时主镜头极缓慢缩放（±0.5%） | 画面不死板 | ✅ |

**全部 5 项已落地**（其中「热点脉冲」经查本就已有，无需新增）。实现要点与避坑：

- **情绪爆发只动 `position:x`**，呼吸 bob 只动 `position:y` —— 两个 Tween 不争抢同一属性，不会互相打断。
- **取证光环**设在 `_remove_clue_circle`：原位生成一圈扩散光环（放大 2× + 淡出 0.36s），与 `clue_found` 音效同步；必须设 `pivot_offset = center`，否则 Control 以左上角为原点缩放会导致整体偏移。
- 光环唯一调用点是 `_close_zoom`（线索成功收集），**不会在清场/切阶段时误触发**。
- **镜头呼吸触发条件刻意收紧**：相机启用 + 未拖拽 + 无相机 Tween 运行 + zoom≈1（统览态），防止与推镜/滚轮打架；幅度仅 ±0.5%、周期 9s。
- **背景交叉淡化**：旧背景改名 `scene_bg_old` 淡出、新背景淡入（各 0.35s），氛围层同步 0.5s 淡入；开头先清理上一次的淡出残留，避免连续切图时堆积。

## 8. 关于 scene1 拆分图（`场景01 拆分.png`）的评估

### 8.1 图的内容
11 个独立像素风家具要素：壁炉（带烛台/炉架）、铺桌布的餐桌、木椅、高书柜、床头柜+绿色台灯、小书柜、花纹窗帘（一对）、金色边框镜子、风景画框、红色波斯地毯、黄铜烛台、绿色台灯（另一角度）。

**优点**：已透明底可直接当 `Sprite2D`；像素风格统一；要素完整；与"拆分真实要素"目标吻合。

**风险**：
1. **风格不匹配**：现有 `screen01-sofa01.png` 是写实/厚涂风，拆分图是像素风，直接拼贴会割裂；
2. **缺关键元素**：沙发、壁炉上方装饰、角色座椅需补；
3. **无坐标/比例**：需按 1920×1080 基准重新缩放定位。

### 8.2 使用建议

| 方案 | 做法 | 成本 | 效果 |
|------|------|------|------|
| A. 直接使用 | 11 件家具拼到 sofa 背景 | 最低 | **风险高**：风格割裂 |
| B. 统一成像素风 | 底图也重渲成像素 | 中等 | 风格统一，整体变像素 AVG |
| C. 重写实风要素 | 以拆分图为清单，按现有底图风格重生成要素 | 中等 | **与现有背景无缝融合，效果最好** |
| **推荐** | **C 方案**：拆分图作为"拆什么"的蓝图，而非直接美术资源 | — | 风格一致 + 要素完整 |
