## 1. 设计要求溯源（三档预期）

设计文档对三档难度的要求，归纳为一句话：**简单＝全提示/引导式，普通＝概率提示+动态调整，困难＝无提示+含误导**。具体落到几个文档：

- **`00_核心设计思路.md` §2.3**（机制模块表）：场景线索提示（高亮/微光/无）、可信度展示、假设引导、矛盾被动提示、福尔摩斯检验次数、验证报告内容、时间时效、凶手行动线 —— 八行逐项差异化。
- **`08_系统框架设计.md` §3.5**（DifficultyManager 规范）：`enum Mode`、`set_mode`、普通基础提示概率 **0.7（与 02 文档一致）**、概率上限 0.95、**动态概率调整（停滞+10%/错误+5%/正常-5%）**、**误导概率（EASY 0 / NORMAL 0.3 / HARD 0.7）**、**困难隐藏提示选项（filter_choices / is_hint_only）**、**差异化提示文本（get_tool_hint / get_progress_hint 全/部分/空）**、**推理墙自动填充（EASY 全 / NORMAL 部分 / HARD 零）**。
- **`08_系统框架设计.md` §8.2**（影响矩阵）：推理墙填充、对话选项（困难隐藏提示）、工具提示、调查进度提示、**竞技难度分数倍率（EASY 0.5× / NORMAL 1.0× / HARD 1.5×）**、概率底线（EASY 100% / NORMAL 动态调整 / HARD 0%）。

## 3. 验证结论：设计 vs 实现对照

### ✅ 已实现并连线（与设计对齐）
1. **场景线索提示**：热点高亮（EASY）/ 微光（NORMAL）/ 无提示（HARD）—— `scene_controller.gd`，真实渲染生效。
2. **对话按难度分支 + 普通概率触发**：`difficulty_filter` + NORMAL `probability`，且 scene3 有独立简单模式起始节点。
3. **困难无被动提示**：`should_show_hint()` 在 HARD 恒 false。
4. **NO_HINT_MASTER 徽章**：困难且未用提示即授予。
5. **难度选择 UI + 顶栏显示**。

### ❌ 设计有但实现缺失 / 偏差（缺口）
| 设计预期 | 代码现状 | 影响 |
|----------|----------|------|
| NORMAL 基础概率 **0.7**（与 02 文档一致） | 代码 `hint_probability = 0.5` | 偏差：普通模式提示频率偏低 |
| **动态概率调整**（停滞+10%/错误+5%/正常-5%，上限 0.95） | 仅有 `dynamic_hint_chance=true` 标志，**无实现逻辑** | 缺失：普通模式「防流失」核心机制未落地 |
| **误导概率**（EASY 0 / NORMAL 0.3 / HARD 0.7） | 完全未实现 | 缺失：困难「含误导」未落地 |
| **困难隐藏提示选项**（filter_choices / is_hint_only） | `DialogueNodeResource` 无 `is_hint_only` 字段，未过滤 | 缺失：困难模式仍可看到提示选项 |
| **差异化提示文本**（全/部分/空） | 仅 `should_show_hint()` 布尔，无文本产出 | 缺失：提示无内容差异 |
| **推理墙自动填充**（EASY 全 / NORMAL 部分 / HARD 零） | `auto_fill_notebook` 仅 EASY 置 true，**无填充逻辑** | 缺失：标志为死代码 |
| **竞技难度分数倍率**（EASY 0.5× / NORMAL 1.0× / HARD 1.5×） | `StarRatingSystem` 完全未施加（仅用难度判徽章） | 缺失：评分与难度无关，偏离 §8.2 |
| 矛盾被动提示按难度、福尔摩斯检验次数限制、验证报告内容差异化、时间时效/线索失效、凶手行动线同步、可信度展示差异化 | 均未实现 | 缺失（属更大扩展，见 §5） |

### ⚠️ 死代码 / 命名偏差
- `show_guidance`、`dynamic_hint_chance`：置位但**全局无读取**（死标志）。
- `auto_fill_notebook`：仅被 `framework_test.gd:92` 测试读取，运行时未消费。
- `detective_scene.gd` `_difficulty`：捕获后未使用（死）。
- 接口命名偏差：设计 `enum Mode` + `set_mode` + `roll_hint_probability`；代码 `enum Difficulty` + `set_difficulty` + `should_show_hint`——内部自洽，但与 `08 §3.5` 伪代码不符（若后续按设计补 `get_mislead_probability` 等，需先统一命名）。

## 5. 结论与建议

**机制骨架已通**：难度选择 → 状态 →（热点渲染 / 对话分支+概率 / 困难徽章 / 顶栏显示）这条链路在运行时真实生效，且 `test_difficulty.gd` 已进 CI。

**但距设计文档的「完整难度适配体系」仍有显著缺口**：设计 `08 §3.5 / §8.2` 规定的动态概率调整、误导概率、困难隐藏提示选项、差异化提示文本、推理墙自动填充、竞技分数倍率六项，当前**均未实现**；其中五项（`dynamic_hint_chance`/`auto_fill_notebook`/`show_guidance`）仅以「置位但无逻辑」的死标志存在。NORMAL 基础概率也与设计 0.7 不符（代码 0.5）。

**建议优先级**（若要做满设计）：
1. **高**：动态概率调整（普通模式防流失，设计核心）、困难隐藏提示选项、竞技分数倍率——三项设计明确、直接影响体验。
2. **中**：误导概率、差异化提示文本、推理墙自动填充。
3. **低/扩展**：矛盾被动提示、检验次数限制、验证报告差异化、线索失效时序、凶手行动线——属更大扩展，建议单列迭代。
