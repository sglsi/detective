# 《谁是大侦探》背景音乐设计方案（音乐总监视角）

> 版本：v1.0 ｜ 适用：当前 8 场景侦探解谜游戏（案件原型为《血字的研究》德雷伯谋杀案）
> 现状：项目**零音频资产**，但 `SettingsManager` 已预留 `music_volume` / `sfx_volume` 两个设置键，`dialogue_manager.get_current_mood()` 已提供情绪驱动源——音乐系统从零设计、接口已留好。

---

## 一、设计目标与原则

1. **为「思考」配乐，而非为「动作」配乐。** 本游戏核心是观察→收集→推理的智力闭环，音乐的职责是维持专注、暗示悬念、在玩家「想通」的瞬间给与智性快感，而不是用强节奏填满时间。
2. **悬疑但不焦虑。** 参考维多利亚侦探美学：雾、煤气灯、马车、伦敦的潮湿感。紧张来自「未知」而非「威胁」。
3. **交互即编曲。** 音乐必须随玩家行为（进场景、开推理墙、对话情绪、线索命中、揭谜）实时重组，而非播放固定长曲。
4. **角色有声音身份。** 用主导动机（leitmotif）让福尔摩斯、华生、受害者、真凶「可被听见」。
5. **零风险落地。** 首版只用纯音乐（无歌词、无版权风险素材），格式全用 Godot 原生 OGG，可程序化生成或外包。

## 二、声音身份定位（Sonic Identity）

| 维度 | 定位 |
|---|---|
| 流派 | 新古典 / 室内乐悬疑（Chamber Neo-Classical Mystery） |
| 编制 | 4–8 人弦乐（小提琴/中提/大提）+ 钢琴 + 竖琴 + 轻打击（钟、节拍器、远雷、脚步） |
| 时代感 | 维多利亚伦敦；可点缀音乐盒、手摇风琴音色作色彩 |
| 调性 | 小调为主，半音化行进；关键真相时刻用大调「破雾」 |
| 参考 | BBC《神探夏洛克》（小提琴动机）、Enola Holmes、雷顿教授（解谜古典）、Ace Attorney（张力爵士）、极乐迪斯科（叙事环境） |
| 母带响度 | 集成响度 −14 LUFS，true peak ≤ −1.0 dBTP（游戏混音惯例） |

**禁忌**：史诗管弦全奏（与「小场景推理」气质冲突）、电子舞曲鼓组、任何带人声的素材（版权/出戏）。

## 三、音乐系统架构

### 3.1 分层交互音乐（Vertical Remix）

每个场景 BGM 不是一首曲子，而是 **4 条可独立升降的音轨（stem）**，由音乐引擎按状态实时混音：

```
┌─────────────────────────────────────────────┐
│           场景 BGM（按 scene_id 加载）         │
│  A 基底层 Bed   ── 低频铺底 + 伦敦雾环境纹理    │ 常驻
│  B 律动层 Pulse ── 钟摆滴答 / 低音拨弦脉冲      │ 推进感
│  C 旋律层 Motif ── 小提琴独奏，承载角色动机     │ 叙事层
│  D 张力层 Tension─ 不谐和 ostinato / 远雷      │ 高潮层
└─────────────────────────────────────────────┘
         ↑ 由「自适应状态机」控制各层音量/滤波
```

### 3.2 自适应驱动源（按优先级）

| 驱动源 | 取自 | 作用 |
|---|---|---|
| 对话情绪 `get_current_mood()` | `dialogue_manager` | 切换 A/B/C/D 分层组合（最强驱动） |
| 游戏状态 | 场景切换 / 推理墙开关 / 结算 | 切换整套 BGM 或触发 stinger |
| 场景 `scene_id()` | 各 `sceneX.gd` | 选对应场景 BGM 包 |
| 难度 | EASY/NORMAL/HARD | 微调混音（HARD 去引导旋律、加重低频压迫） |

### 3.3 总线与播放架构（Godot）

- 新建 `default_bus_layout.tres`：`Master → {Music, SFX, Ambience, Stinger, Voice}`
- `Music` 总线增益绑定 `SettingsManager.music_volume`；`SFX` 绑定 `sfx_volume`
- `MusicDirector`（autoload 单例）持有 4 个 `AudioStreamPlayer`（每层一个，均路由到 `Music` 总线），负责：
  - 场景切换时的 crossfade（2–3s 淡入淡出）
  - 订阅对话情绪 → 调各层 `volume_db` / 低通滤波
  - 提供 `play_scene_bgm(id)` / `set_mood(state)` / `play_stinger(id)` API
- 所有 stem 用 `AudioStreamOggVorbis` 并设 `loop = true`（无缝循环，8–16 小节）

## 四、音乐素材清单

### 4.1 流程节点 BGM（非场景）

| ID | 节点 | 气质 | 分层建议 |
|---|---|---|---|
| MENU | 案件主界面 / 主菜单 | 优雅、邀请感、留白 | A+C（动机轻声） |
| DIFFICULTY | 难度选择 | 中性、略带抉择重量 | A+B 轻 |
| REASONING_WALL | 推理墙 / 思维殿堂 | 水晶般澄澈、智性升腾 | A+C 高频泛音 + 竖琴 |
| CLUE_LOG | 线索记录与分析 | 整理感、平稳 | A+B |
| SETTLEMENT | 案件结算 / 星级评定 | 成果兑现，按星级起伏 | A+C，星级升则加明亮层 |

### 4.2 场景 BGM（scene1–8，详见第六节）

每个场景交付一整包 4-stem 分层素材（共 8 包 × 4 = 32 条 stem + 流程曲 5 包）。

### 4.3 角色主导动机（Leitmotif）

| 动机 | 音色 | 音型特征 | 出现时机 |
|---|---|---|---|
| 福尔摩斯 | 独奏小提琴 | 小调上行跳进（小三度+纯五度），附点节奏，智性、跳跃 | 华生旁白推理、玩家推进逻辑链 |
| 华生 | 中提琴 | 温暖三度伴行，叙事感、陪伴 | 教学关、向导性对话 |
| 血字 / 受害者德雷伯 | 低音弦 + 钟琴 | 不祥半音下行主题（"墙上的血字"） | 命案现场、提及死者 |
| 真凶（报复） | 大提琴长音 + 不协和下二度 | 压抑、隐忍；揭示时转为悲悯 | 逼近真相、终局揭谜 |
| 伦敦雾（环境母题） | 风声 + 远处汽笛 | 可贯穿的 city texture | 作所有场景基底 A 层底色 |

### 4.4 事件 Stinger（1–3s 短 cues，路由 Stinger 总线）

| ID | 触发 | 听感 |
|---|---|---|
| CLUE_FOUND | 收集到一条线索 | 轻「啊哈」拨弦 + 铃音上行 |
| WALL_LINK_OK | 推理墙连线/关系成立 | 确认感上升音（五度跳进） |
| WALL_CONFLICT | 推理矛盾/错误 | 低沉警示（半音撞音） |
| WALL_OPEN | 进入推理墙 | 竖琴泛音「思维殿堂」入场 |
| REVEAL | 真相大白 | 全奏 reveal（动机交织爆发） |
| SHOCK | 惊吓/危机 | 急促弦乐 glissando |
| STAR_UP / STAR_DOWN | 结算星级升降 | 变现式上行/下行琶音 |

## 五、自适应音乐状态机

把对话情绪 + 游戏状态归并为 6 个规范态，映射到分层音量（0–1，1=满混音）：

| 状态 | 触发 | A 基底 | B 律动 | C 旋律 | D 张力 | 音色处理 |
|---|---|---|---|---|---|---|
| IDLE 平静 | neutral / 探索空闲 | 1.0 | 0.2 | 0.3 | 0.0 | 全开、暖 |
| CURIOUS 探究 | curious / suspicion | 1.0 | 0.6 | 0.5 | 0.1 | 轻微提升 B |
| TENSE 紧张 | tense / 调查推进 | 0.9 | 0.9 | 0.7 | 0.4 | B 加脉冲、D 隐现 |
| DREAD 危机 | dread / 危险逼近 | 0.8 | 1.0 | 0.6 | 0.8 | 低通收紧、D 主导 |
| REVEAL 揭晓 | shock / 真相时刻 | 1.0 | 0.5 | 1.0 | 1.0 | 全层齐鸣后回落 |
| RESOLVE 收束 | triumph / 结案 | 0.8 | 0.0 | 1.0 | 0.0 | 只留 C 动机澄澈收尾 |

> 实现：对话数据中的 `mood` 字段标准化为上述 6 态之一（现有数据多为 `neutral`，需对话组补全 serious/tense/shock 等标签）；`MusicDirector.set_mood()` 用 `Tween` 在 1.5–2.5s 内平滑过渡各层 `volume_db`，避免突变。

## 七、制作规格与管线

**格式与交付**
- 容器：OGG Vorbis（Godot 原生，体积极小）
- 采样率：44.1kHz；码率 BGM 128–160kbps、stinger 192kbps
- 循环：每 stem 8–16 小节无缝循环，标注 loop 起止
- 分层交付：每个场景**单独交付 A/B/C/D 四条 stem**（非合并），供引擎实时混音
- 时长：场景 bed 60–120s 可循环；菜单曲 90s；stinger 1–3s

**编制/素材**
- 优先真实室内乐录音（4–8 人弦乐 + 钢琴/竖琴 + 轻打击）；也可用高质量音源/AI 生成，统一母带
- 环境纹理（风、远雷、马车、煤气灯噼啪）单独录/采，作 Ambience 总线循环层

**生产建议（两步走）**
- MVP 阶段：先用程序化/库素材快速出 1 套场景 bed + 3 个核心 stinger 验证系统
- 完整阶段：按本方案 8 场景 × 4 stem + 流程曲 + 动机 + 全 stinger 正式制作并母带

## 八、Godot 实现指引（对接现有钩子）

1. **总线**：新建 `default_bus_layout.tres`，建 `Master→Music/SFX/Ambience/Stinger/Voice`；`res://project.godot` 的 `audio/buses` 指向它。
2. **设置对接**：`MusicDirector` 在 `_ready` 读取 `SettingsManager.get_setting("music_volume")` 设 `Music` 总线 `volume_db`；监听 `music_volume` 变更。
3. **情绪对接**：每帧或信号式读取 `dialogue_manager.get_current_mood()`，映射到第五节 6 态并 `set_mood()`。
4. **场景对接**：在 `detective_scene.gd` 的 `_ui.setup(...)` 调用后（已有 `scene_id()` 透传），由 `MusicDirector.play_scene_bgm(scene_id())` 切换场景 BGM 包。
5. **推理墙/结算**：`graph_view_controller.gd` / 结算界面在开墙、连线成功/矛盾、星级变动时调用 `MusicDirector.play_stinger(...)`。
6. **数据驱动**：`music_cues.tres`（或 json）维护 `scene_id/mood → stem 包 & 分层强度` 映射，`MusicDirector` 只读此表，策划可不经程序改配乐。

### 已交付
1. **总线布局** `default_bus_layout.tres`：Master + Music / SFX / Voice / Ambience / Stinger（命名与 AudioManager 及 SettingsManager 完全一致）。`project.godot` 的 `[audio]` 段指向它。
2. **AudioManager 扩展**：新增 `SCENE_BGM`（menu + scene1..8 映射）、`STINGERS`（clue_found / wall_conflict / reveal）两张数据表；新增 `play_scene_bgm(id)`、`play_stinger(id)`；`_ready` 内连接 `ClueEventBus.clue_recorded → play_stinger("clue_found")`。
3. **占位音频资产** `assets/audio/bgm/*.wav`（菜单 + scene1–8，各用不同基频便于验证切换）+ `assets/audio/sfx/*.wav`（3 个 stinger），均为 Python 标准库生成的无缝循环低音量 WAV。
4. **接线**：`main_menu.gd._ready` → `play_scene_bgm("menu")`；`detective_scene._build_ui` → `play_scene_bgm(scene_id())`（覆盖全部场景，含教学关 sceneX）；`SettingsManager._ready` 补「启动重 apply 音量」修复读档后音量不生效。

### 关键坑（已修）
- **Godot 4.7 移除 `AudioStreamPlayer.loop` 属性**：BGM 循环改由流资源自身控制，故在 `play_bgm` 内对 `AudioStreamWAV` 设 `loop_mode = LOOP_FORWARD`，而非 `bgm_player.loop = true`（后者会触发「Invalid assignment 'loop'」编译/运行错误）。

### 验证
- `--check-only` 静态检查 PASS（`AudioManager`/`SettingsManager`/`detective_scene`/`main_menu` 全编译）。
- 冒烟测试：9 个 BGM cue + 3 个 stinger 路径均能 `load` 为合法 `AudioStream`（SMOKE_DONE ok=true）。
- Web 重导出 EXIT=0，`index.wasm` 字节数核对一致（39509339），`default_bus_layout.tres` 已进 pck。

### 已知问题与修复（用户实测「没声音」后）
- **根因① Web 自动播放策略拦截**：菜单/场景 BGM 在场景 `_ready`（用户无任何手势）即 `play()`，浏览器将 AudioContext 挂起并丢弃该次播放，Godot 不会自动重播 → 全程静音。
  - 修复：BGM 在首次用户手势（鼠标按下/键盘按下）前只记录「期望 BGM」（`_pending_bgm`），由 `AudioManager._input` 监听首次手势触发 `_unlock_audio()` 补播；`project.godot` 的 `[audio]` 段键名由误写的 `buses/bus_layout` 修正为规范 `bus_layout`（探查证实引擎已兜底加载总线，但键名不规范）。
- **根因② 占位音电平过低**：首批 Python 生成的无缝循环 WAV 峰值约 -18.4 dBFS（满音量 12%），虽非静音但偏轻，易误判无声。
  - 修复：全量增益 ×4（峰值约 -6 dBFS，明显可闻且不削波）。
- 测试要点：浏览器加载 Web 版后**必须硬刷新（Ctrl+Shift+R）**以丢弃旧 `index.pck`；进入游戏后**点击画面或按任意键**即解锁音频（浏览器策略要求首次手势）。
