## 0. 现状基线与 E-26 方案评估

### 0.1 当前架构（事实，非设想）
- 场景脚本基类 `scripts/scene/detective_scene.gd`（`class_name DetectiveScene extends Control`）；场景框架 `scripts/ui/scene_framework.gd`（`extends Control`）。
- 背景：`SceneFramework.set_scene_background(tex: Texture2D)` 用 `TextureRect` 贴单张图。
- 立绘：`SceneFramework.add_portrait(tex, name_text, pos, size, flip) -> Control`（`_make_portrait` 内部实现）。
- 线索圈：`ClueObserver`（`scripts/clue/clue_observer.gd`）在立绘控件上按 `data/clue_image_anchors.gd` 的 `cx/cy/w/h` 画高亮圆圈 + 放大观察层。
- **运行时没有任何 `Camera2D`**：现有场景是「点击热点 + 对话」的定点交互，无 Node2D 世界、无角色移动、无碰撞/关卡几何。
- 例外先例：工程内 `scenes/london_background.tscn` + `scripts/ui/london_background.gd` 已用 `Camera2D`（`@onready var camera: Camera2D = $Camera2D`），证明 Camera2D 可接入本工程。

### 0.2 用户提供的 E-26 方案评估（「扣子生成」）
**优点（✅ 可直接借鉴）**
- `CameraController` 独立节点 + 模式枚举（FOLLOW / FIXED / OVERVIEW / ZOOM_INSPECT）拆分清晰。
- `lerp` 平滑插值做镜头过渡是标准做法。
- FIXED / OVERVIEW / ZOOM_INSPECT 三种模式在「无角色」前提下也能直接用。

**关键缺陷（⚠️ 决定可行性，不能直接套）**
- **FOLLOW 模式 = 换范式**：需 WASD 角色 + 碰撞 + 可行走区域 + 寻路，与现有「点击搜证」冲突（是替代不是增补），数周量级。
- **滚轮缩放未实现**：原方案在 InputMap 声明了 `zoom_in/zoom_out` 但 `camera_controller.gd` 没读滚轮事件——而「按喜好调远近」恰是你最看重的诉求。
- **硬编码节点路径**（`/root/Scene/CameraController` 等）场景树一变就崩；应改为 autoload（如 `CameraManager`）或信号总线 / Group。
- **重新发明内置能力**：`Camera2D.position_smoothing_enabled` + `limit_*` 已能做平滑跟随与边界，手写 `lerp`+`clamp` 冗余且边界逻辑有瑕疵（clamp 的是 target 非相机自身）。
- **2D 上帝视角 ≠ 真 3D 俯瞰**：OVERVIEW 只是 `zoom<1` 看全屋，不能旋转——需先对齐预期。

**结论**：E-26 的「思路」可用，「实现」需重做以适配本工程 Control 架构；角色走动作为**远景大里程碑独立立项**。

## 1. 总目标（Vision）
把游戏从「静态点击场景」升级为「玩家可自由观察、场景随视角变化、关键处可推近看细节、人物有生命感」的动态体验——**且不破坏已有点击搜证玩法与 8 个场景的剧情完整性**。

两层诉求：
- **观察层（必做、低风险）**：上帝视角统览全场景、滚轮/捏合自由调远近、拖拽平移、点线索自动推近（zoom-to-clue）。
- **运动层（远景、可选）**：人物待机微动 → 可选角色可走动探索。

---

## 2. 设计原则（落地约束）
1. **不破坏现有玩法**：点击搜证、对话、推理墙逻辑零改动；摄像机只作为「外层观察封装」。
2. **世界层 / UI 层分离**：背景 + 立绘 + 线索圈归入「世界子树」，由 Camera2D 驱动平移缩放；对话栏 / 工具栏 / 推理墙 / 评价面板放入独立 `CanvasLayer`（layer > 0），**永不随镜头缩放变形**。
3. **复用而非重写**：优先基于 `london_background.gd` 的 Camera2D 先例 + `07_地图系统迁移方案` 的缩放/平移/边界写法；`ClueObserver` / 放大镜直接复用做 zoom-to-clue。
4. **每阶段独立可验、可回滚**：阶段一重构若影响点击命中，保留原 Control 布局作 fallback（世界子树封装可开关）。
5. **Web 一致**：所有改动走 detective 验证 SOP（见 §7），重导出并注入 pck 版本。

|---|---|---|---|---|---|
| 一 | 摄像机 / 观察层 | 近期·核心 | 统览 + 缩放 + 平移 + zoom-to-clue | 低 | 1–2 天 |

## 4. 阶段详述

### 阶段一：摄像机 / 观察层（近期·核心，立即启动）
**目标**：玩家以上帝视角统览场景，按喜好滚轮 / 拖拽调远近与位置，点线索时镜头平滑推近到该部位。

**涉及文件 / 新增**
- 新增 `scripts/camera/camera_manager.gd`（建议 autoload `CameraManager`，避免硬编码路径）：封装一个 `Camera2D`，提供 API：
  - `overview(zoom := 0.4)` / `reset()`：统览全屋 / 回到默认 1.0。
  - `zoom_by(factor)`：读滚轮 / 捏合增量改 `camera.zoom`，`clamp(min, max)`。
  - `pan(delta: Vector2)`：拖拽改 `camera.position`（限 OVERVIEW 模式）。
  - `zoom_to_rect(rect: Rect2, margin := 1.2)`：tween 到线索锚点区域（zoom-to-clue）。
  - `set_limits(rect: Rect2)`：用 `camera.limit_*` 限制可视范围（复用 07 方案）。
  - 平滑：`camera.position_smoothing_enabled = true` + `position_smoothing_speed`（用内置，不手写 lerp）。
- 改造 `SceneFramework`：将「世界子树」（背景 `TextureRect` + 各 `add_portrait` 立绘 + 线索圈）包进统一容器；搭好 Camera2D 挂载点（参考 `london_background.gd`）。
- UI 层迁移：对话栏 / 工具栏 / 推理墙从默认层移入 `CanvasLayer`（layer ≥ 1），确保不被缩放。
- 输入：InputMap 加 `wheel_up` / `wheel_down`（+ 触屏 `screen_drag` / `pinch` 预留），由 `CameraManager` 消费（**补上 E-26 漏掉的滚轮缩放**）。
- 键位：`Tab` = 切 OVERVIEW 统览；`Esc` / 再按 = `reset()`。

**交付物**：scene1 原型——可滚轮缩放、拖拽平移、Tab 统览、点信使线索镜头推近到锚点（复用 `ClueImageAnchors`）。

**验收**
- 点击命中区与缩放前一致（线索圈仍可点）；
- UI 层（对话栏 / 工具栏）缩放时位置 / 尺寸不变；
- 走 §7 SOP。

**风险 / 回滚**：若世界子树封装导致点击命中偏移，保留 `SceneFramework` 原布局为 fallback（封装开关 `use_camera_layer`）。

### 阶段二：立绘待机动画（近期·低成本）
**目标**：人物「看起来在动」，不必走动即有生命感。

**涉及**：`SceneFramework.add_portrait` / `_make_portrait` 返回的 Control 加 tween：
- 呼吸：`scale.y` 微抖（±0.5%）+ `position.y` 微浮（±2px），错相周期。
- 福尔摩斯 / 华生 / 信使差异化节奏。
- 进入对话 / `_obs` 激活时暂停待机（避免干扰阅读）。

**验收**：headless 难测动画，靠 Web 目视；`--check-only` 零错误即可。风险低。

### 阶段三：模式系统接入叙事（中期）
**目标**：把镜头变成叙事语言——开场预设机位、对话节点触发推近 / 拉远。

**涉及**
- 定义 `CameraMode` 枚举（FIXED / OVERVIEW / ZOOM_INSPECT），由对话节点指令触发。
- 对话资源 `DialogueNodeResource` 增可选 `camera` 字段（焦点框 / zoom 值）；`DialogueManager._go_to_node` 应用时调 `CameraManager`。
- 场景开场 / 转场：`SceneTransition` 淡入淡出 + tween 到 FIXED 机位（复用 07 方案）。
- ZOOM_INSPECT 与 `ClueObserver` 打通：观察线索即镜头推近（阶段一 `zoom_to_rect` 已具备）。

**验收**：场景二~八开场机位符合设计；对话中镜头变化不卡对话推进（测 `_obs.hide()` 守卫仍有效）。

### 阶段四：角色走动探索 FOLLOW 模式（远景·大里程碑，独立立项）
**目标**：玩家操控 avatar 在场景内走动，镜头跟随。

**前置评估（须先确认）**
- 需补：可行走精灵 + 待机 / 行走动画（`AnimationPlayer` / `AnimatedSprite2D`）、`CharacterBody2D` + 碰撞、`TileMapLayer` 可行走层、简单寻路、`WASD` / 触屏摇杆。
- 与定点搜证的关系：二选一（纯探索解谜）或切换（探索找线索 → 切回定点对话）。
- 工作量：数周量级，建议**单独立 Git 分支 / 独立任务**，不影响阶段一~三已交付。

**参考**：`07_地图系统迁移方案` 的 `Camera2D` 跟随 + `08_系统框架设计.md` 的 TileMapLayer 架构；E-26 的 FOLLOW 模式思路（但须去硬编码、用内置平滑）。

### 阶段五：Parallax 氛围背景（远景·可选）
- 仅当镜头真移动时有意义；需把每张背景重做 4 层 PNG（远 / 中 / 近 / 前），美术成本高。放最后，按资源情况决定。

## 5. 统一技术底座：CameraManager 设计草案（供阶段一落地）

```gdscript
# scripts/camera/camera_manager.gd  (autoload: CameraManager)
extends Node
var _cam: Camera2D
var _min_zoom := 0.3
var _max_zoom := 2.5

func attach(cam: Camera2D) -> void:
    _cam = cam
    _cam.position_smoothing_enabled = true
    _cam.position_smoothing_speed = 8.0

func overview(z := 0.4) -> void:
    _cam.zoom = Vector2(z, z)

func reset() -> void:
    _cam.zoom = Vector2.ONE
    _cam.position = Vector2.ZERO

func zoom_by(f: float) -> void:
    _cam.zoom = (_cam.zoom * f).clamp(Vector2(_min_zoom, _min_zoom), Vector2(_max_zoom, _max_zoom))

func zoom_to_rect(r: Rect2, m := 1.2) -> void:
    # tween _cam.zoom + position 到 r 居中放大 m 倍
    pass

func set_limits(rect: Rect2) -> void:
    _cam.limit_left = rect.position.x
    _cam.limit_top = rect.position.y
    _cam.limit_right = rect.end.x
    _cam.limit_bottom = rect.end.y
```
> 注：以上是骨架，落地时按 `london_background.gd` + `07_地图系统迁移方案` 第 538–560 行补全（含 tween 与触屏 pinch）。

## 6. 与现有代码集成的关键 seam
- `SceneFramework.setup()` 目前建背景 + 立绘；阶段一在其内增加「世界子树」容器与 `Camera2D` 挂载，并调用 `CameraManager.attach(cam)`。
- `ClueObserver._open_zoom()` / `_mark_clue_at_anchor()` 已持有锚点 `Rect2` 概念；阶段一让点击线索时改调 `CameraManager.zoom_to_rect(anchor_rect)`，观察器关闭时 `CameraManager.reset()`。
- `DetectiveScene` 基类提供 `_prompt_think` / `_observe_hint` 等；阶段三的对话 `camera` 指令在 `_start_dialogue` 链路里接入，不改动剧情文本。
